# first-try-article-skill

> 把一篇文章，转成一组**忠于原文**的知识卡片。

输入一篇长文（粘贴文本，或指向本地文件），输出若干张知识卡片。每张卡片恰好讲一个知识点，包含 **标题 / 核心内容 / 批注解释** 三部分。

---

## 项目功能

| 功能 | 说明 |
|---|---|
| **文章 → 知识卡片** | 输入任意长文，输出结构化卡片；粘贴文本或提供文件路径（`.md` / `.txt` / `.docx` / `.pdf`）均可 |
| **卡片三要素** | 每张卡片 = 标题 + 核心内容 + 批注解释 |
| **一张卡一个知识点** | 内容讲多了就拆开，讲重了就合并 |
| **忠实原文** | 核心内容必须能回溯到原文；`「」` 内为逐字引用并标注段落，严禁篡改、夸张、脑补 |
| **来源分离** | 原文的话与编者的解读物理分开；外部知识标 `补充：`，推断标 `推断：` |
| **多类型适配** | 科普 / 议论文 / 教程 / 论文 / 新闻 / 散文各有切分策略；议论文自动把论断标注为"作者认为" |
| **长文支持** | 超过约 3000 字时按原文章节分组处理（实测：鲁迅《我之节烈观》约 5600 字 → 33 张卡片，分 8 组） |
| **双重校验** | 人工自检清单 + `tests/fidelity_check.py` 自动逐字核对所有引用 |
| **可视化输出** | 可选渲染成 HTML 卡片组，便于阅读与分享 |

## 项目创建目的

市面上的"文章总结"工具，问题通常不在信息量，而在**忠实度**：为了行文通顺而改写了原意，为了内容好看而补上原文没有的结论，把作者的观点直接写成了客观事实。用于笔记、复习、知识沉淀时，这类"加工过的摘要"反而有害——你记住了，但记住的不是原文的意思。

这个项目的目标很窄，也很明确：**做一把不篡改原文的"拆解刀"。**

1. **原子化** —— 把长文拆成可以单独复习的卡片，而不是压缩成一段摘要；
2. **可回溯** —— 任何一句核心内容都能指回原文的位置，经得起逐字核对；
3. **来源分离** —— 编者的解释与原文严格分开，读者一眼能分清"哪句是作者说的，哪句是拆解者补的"；
4. **可机械验证** —— 附带忠实度检查脚本，让"不篡改"不只是一句口号。

同时，这也是作者的第一个 Skill 项目（"first try"），用于走通"写规范 → 实现 → 用真实文章测试 → 按测试结果迭代"的完整流程。这一流程确实起了作用：本地测试中，自动检查抓到过一处"伪引用"（把原文 `不在于"读完"了多少字` 写成了 `不在于读完了多少字`），随后据此在规范中增补了"引用必须逐字"这条铁律。

## 使用方法

### 1. 安装为 Skill

把整个目录放进技能目录（二选一）：

```bash
# 用户级：所有项目都能用
cp -r first-try-article-skill ~/.workbuddy/skills/

# 项目级：仅当前仓库可用
cp -r first-try-article-skill <项目>/.workbuddy/skills/
```

### 2. 触发

在对话里直接说，例如：

- "把这篇《睡眠如何为记忆存档》转成知识卡片"
- "拆解这篇文章，做成卡片，注意不要改原意"
- "帮我把这份报告提炼成复习卡片"

触发词：知识卡片、文章转卡片、拆解文章、提炼要点、做成卡片、读书卡片、knowledge cards。

### 3. 得到输出

默认输出 Markdown 卡片，可直接写在对话里，或保存为 `.md` 文件。

### 4. 可选：渲染成页面 / 自动校验

```bash
# 渲染成 HTML 卡片组（浏览器打开）
python scripts/render_deck.py examples/01-popular-science.cards.md -t "睡眠与记忆 · 知识卡片"

# 逐字校验所有「」引用是否来自原文
python tests/fidelity_check.py tests/fixtures/01-popular-science.md examples/01-popular-science.cards.md
```

## 输入输出示例

### 示例一：一段原文 → 两张卡片（完整最小示例）

**输入**（`tests/fixtures/03-tutorial.md` 第 1 段）

> 番茄工作法的核心是把工作切成固定的短周期：专注 25 分钟，然后休息 5 分钟，完成四个周期后再进行一次较长的休息（通常 15 到 30 分钟）。它的原理不是逼自己更努力，而是用固定的短周期降低"开始工作"的心理门槛。

**输出**（`examples/03-tutorial.cards.md` 前两张）

```markdown
## 番茄工作法的标准周期：25 分钟专注 + 5 分钟休息

**核心内容**
「专注 25 分钟，然后休息 5 分钟，完成四个周期后再进行一次较长的休息（通常 15 到 30 分钟）」（第 1 段）。

**批注解释**
25 / 5 / 15–30 是原文给出的默认值；"通常"表明长休息时长并不固定。

---

## 番茄工作法靠降低"开始"的心理门槛起作用

**核心内容**
它的原理「不是逼自己更努力，而是用固定的短周期降低"开始工作"的心理门槛」（第 1 段）。

**批注解释**
关键在降低"启动阻力"，而不是比拼意志力。
```

注意两处细节：一段原文含两个知识点，被拆成两张卡；核心内容全部来自原文，编者的解读只出现在"批注解释"里。

### 示例二：四篇文章的实测产出

| 文章 | 类型 | 输入（原文） | 输出（卡片） |
|---|---|---|---|
| 睡眠如何为记忆存档 | 科普说明文 | `tests/fixtures/01-popular-science.md` | `examples/01-popular-science.cards.md`（7 张） |
| 别让深度阅读悄悄消失 | 论点议论文 | `tests/fixtures/02-argumentative.md` | `examples/02-argumentative.cards.md`（6 张） |
| 用番茄工作法建立专注节奏 | 教程操作类 | `tests/fixtures/03-tutorial.md` | `examples/03-tutorial.cards.md`（7 张） |
| 鲁迅《我之节烈观》 | 议论文（长文） | `tests/fixtures/04-luxun-jielieyuan.md` | `examples/04-luxun-jielieyuan.cards.md`（33 张） |

每份产出都同时提供 `.md` 源文件与渲染后的 `.html` 卡片组，可直接在浏览器打开查看。

### 示例三：长文（约 5600 字）的实测产出

前 3 篇是为测试而写的短文（各约 600–800 字）；这一篇是真实长文，用来检验长文分组能力。

**输入**：鲁迅《我之节烈观》（1918）全文，约 5600 字，议论文（杂文）。

**输出**：`examples/04-luxun-jielieyuan.cards.md`，**33 张卡片，按原文自身章节分 8 组**：

| 分组 | 卡片数 | 内容 |
|---|---|---|
| 一、"人心日下"的叹声与新的"挽救"之法 | 7 | 引子：叹"日下"的话术，与"表彰节烈"的出场 |
| 二、"节烈"的界定 | 5 | "节"与"烈"各指什么、如何评价 |
| 三、作者提问的立场 | 1 | 声明批判对象是"多数国民的意思" |
| 四、第一层疑问：依"旧日常识"的诘问 | 4 | 三个疑问 + 一个附带疑问 |
| 五、第二层疑问：带上"二十世纪气息" | 3 | 节烈是否道德、谁有资格表彰 |
| 六、节烈的来历 | 6 | 从殉葬、宋代"业儒"到"被征服"的地位 |
| 七、难、苦、不愿 | 4 | 难、苦、不节烈也苦、本人不愿 |
| 八、结论与发愿 | 3 | 结论、哀悼的价值、三条发愿 |

长文的处理方式：按原文章节用 `###` 分组；段落编号以自然段为单位；议论文的全部论断标注为"作者认为 / 作者主张"，不写成事实。

### 示例四：议论文的归属处理（节选）

议论类文章里，观点属于作者。卡片会保留这一层归属，而不是把作者的主张写成事实：

```markdown
## 作者主张：应把深度阅读当作需要刻意保护的能力

**核心内容**
作者认为「我们应当有意识地保护深度阅读，把它当成一种需要刻意练习的能力」（第 1 段）。

**批注解释**
这是全文的中心主张，属于作者立场，不是客观结论。
```

## 卡片格式

```markdown
## <标题：一句能独立成立的陈述>

**核心内容**
<忠于原文；`「」` 内为逐字引用并标注段落；最小改写不加引号>

**批注解释**
<术语/背景/重要性/边界；外部知识用"补充："，推断用"推断：">

---
```

标注约定：

- `「…」`（第 N 段）：逐字引用的原文，省略处用 `「前……后」`。
- 无引号的核心内容：对原文的最小改写，语义等同。
- `补充：` / `推断：`：批注中的外部知识 / 编者推断。

> 注：卡片标题用 `##`；概览等非卡片文字不用 `##`，章节标题可用 `###`，以免被渲染脚本误当成卡片。

## 设计原则

- **可回溯**：核心内容的每句话都能在原文指出对应位置。
- **保留限定**：原文的"通常/可能/在……条件下"等限定词一律保留，不升级为必然。
- **来源分离**：原文观点与编者解读物理分开，外部知识与推断有明确标记。
- **原子化**：一张卡片只讲一个知识点。
